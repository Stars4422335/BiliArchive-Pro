### 实测数据（2 万资产）:
- WebUI 资产列表 9.46ms -> 0.11ms（87x）
- WebUI 计数 8.12ms -> 0.68ms（12x）
- 三项合计 27.99ms -> 14.03ms（2.0x）

### Notes:
**本次最重要的一次纠错——删掉自己刚加的索引。**
最初为 candidates_for_verify 建 idx_assets_verify，基线显示 10.4->3.1ms，
看似成功。但基线数据里 last_verify 全为 NULL，不具代表性。
用真实分布复测后发现三种填充率下全部更慢：
  0%   填充: 6.37 -> 13.88ms（慢 2.2x）
  50%  填充: 5.70 -> 18.10ms（慢 3.2x）
  100% 填充: 11.34 -> 108.37ms（慢 9.6x）
原因：其排序键 ORDER BY last_verify IS NOT NULL 也是表达式，SQLite 用不上
索引排序，反而要为每个匹配行回表取 last_verify 再排临时 B-tree。
教训：索引收益高度依赖数据分布，用失真的基线做决策会得到相反结论。

- db_wal 默认关闭：WAL 需在库同目录建 -wal/-shm，只读挂载或部分网络盘会失败。
  已验证 WAL 下 WebUI 的 mode=ro 完全兼容（含写事务进行中读取）
- 刻意不优化 candidates_for_verify：它每 6 小时才跑一次，不在交互路径上，
  而 WebUI 是用户每次打开都要用的。优化交互路径优先
- 未做：深分页（OFFSET 万级仍需扫描）、candidates_for_verify 的表达式排序
- 下一步：M4 剩余——AI 内容摘要（涉及内容外发隐私，需先定 API 选型）、
  UP 主图文投稿同步

## 2026-10-14 - Task: M4 弹幕词云（README TODO #5，已完成）

### What was done:
- 新增 app/core/wordcloud.py：DanmakuWordCloud 类
  * extract_terms()：解析 .danmaku.xml，按词频降序返回高频词
  * tokenize()：中文取字符二元组 + 保留整串；英文/数字串整体保留
  * render_svg()：拼装 SVG，权重按排名平方衰减（头部词显著更大）
  * generate()：编排，失败一律返回 False 不抛异常
- danmaku.py：_parse_comment 提升为公开 parse_comment，供词云复用，
  保证词云与 ASS 转换看到完全同一批弹幕
- downloader.py：_convert_downloaded_danmaku 由 staticmethod 改为实例方法
  （需要 self.config 读 wordcloud 配置），转换后顺带触发词云生成
- config.yaml：新增 wordcloud 块（enabled 默认 false / max_terms 默认 60）

### 设计决策（与计划书原方案的差异）:
- **零新依赖**：放弃 wordcloud + jieba + matplotlib。理由：
  ① jieba 需词典/模型文件，对弹幕这种噪声文本收益有限；
  ② matplotlib 在 build.spec 里被显式排除，引入会与打包配置冲突；
  ③ 位图字体在三平台渲染不一致，SVG 无此问题且体积仅几十 KB
- **bigram 而非词典分词**：弹幕是极短高频口语，二元组能自然捕获
  「前排」「泪目」「gg」等模式，完全确定、无外部资源、单测可断言
- **只生成不阻断**：XML 损坏/词数不足/渲染异常/max_terms 非法均降级为提示，
  不影响视频下载与 NFO 写入的完成状态判定（与孤本保护精神一致）
- **不生成 PNG/JPG**：原计划存为 poster.jpg 备选风格或 fanart.jpg，
  但那会与 Plex/Jellyfin 标准封面冲突。SVG 侧车不覆盖任何既有文件

### Testing:
- 新增 tests/test_wordcloud.py 31 例，覆盖三类风险：
  ① 分词噪声（应答词/纯符号/单字/ASCII 切分/去重/上限）
  ② 失败语义（损坏 XML/词数不足/生成器内部抛异常均不外泄）
  ③ 输出安全（SVG 对 < > & " 做 XML 转义，无法注入标签）
  ④ 确定性（固定种子，同输入同输出）
  ⑤ downloader 集成（关闭时不生成/开启时生成/转换后顺带触发）
- 全量 228 passed（197 + 31）
- 修正 process：_convert_downloaded_danmaku 改实例方法后，
  test_downloader.py 里两处类调用需改 _bare_downloader() 辅助

### Notes:
- 实现过程中修正了自己写出的 3 个真实缺陷（均由新测试暴露）:
  1. _generate_wordcloud 用 xml_path.rsplit()，传 Path 对象直接
     AttributeError——补 os.fspath() 转换
  2. tokenize 先删标点空格再切词，导致 "GPU FOMO" 被粘成 "gpufomo"
     ——改为先按空白切块再逐块处理
  3. 噪声词表把「前排」「打卡」当噪声滤掉，但它们高频且有语义，
     恰是词云最有价值的部分——移出噪声表，并补测试锁定该行为
- 遗留：WebUI 无词云浏览入口（当前只能直接看文件）；未做 PNG 导出
- 下一步：M4 剩余——AI 内容摘要（涉及内容外发隐私，需先定 API 选型）、
  性能治理（万级资产分页优化 / SQLite WAL）

## 2026-10-14 - Task: M3-F4 跨平台自动发版流水线（已完成）

### What was done:
背景：build.spec 在 v1.4.0 已完成并本机验证（52MB 单目录产物），但每次发版
都靠手工跑打包 + 手工上传 Release。本任务把这条路径自动化。

- 新增 .github/workflows/release.yml，三作业依赖链：
  source（源码 ZIP）→ build（三平台矩阵）→ publish（统一转正式）
- 平台矩阵：windows-latest / macos-latest(arm64) / ubuntu-latest。
  关键约束：PyInstaller 不能交叉编译，所以三平台各占独立 runner，
  而不是矩阵里可替换的一个维度
- 每个平台构建流程：Ensure archive tools → PyInstaller 构建 →
  --version 冒烟并与 app/__init__.py 比对 → 关键依赖完整性检查
  （yt_dlp/bilibili_api/defusedxml/uvicorn）→ 打包 → SHA256 → 上传
- source 作业用 git archive 生成源码 ZIP，并审计条目：
  config.local.yaml / data/ / downloads/ / venv/ / 本地任务记录 命中即失败
- 发布策略：三平台产物先传草稿，全部成功后 publish 才转正式。
  任一平台失败不会产生正式 Release
- 产物内附 config.yaml / LICENSE / README.md / bin/ 空目录 / 中文安装说明
- 权限最小化：contents: write
- 文档同步：DEVELOPER_GUIDE 新增「自动化发版」小节、README 与 README.en.md
  打包章节改为「推送标签自动产出三平台」、CHANGELOG Unreleased、
  完善计划书 v5 + F4 执行记录

### Testing:
- YAML 解析与结构校验通过（.mimosa/check_release_yml.py）：
  触发器/作业链/矩阵/权限/必需步骤全部符合预期
- 断言三平台均为原生 runner（无交叉编译）
- 断言无 SIGPIPE 风险模式、无 CR 字符、无 PowerShell 语法混入
- 断言源码归档含敏感路径审计
- 未在真实 CI 上跑过（需推送 tag 触发），本地无法验证 PyInstaller
  在 macOS/Linux runner 上的真实产物

### Notes:
实现过程中修正了自己第一版写出的 4 个真实缺陷：
1. Package 与 Generate SHA256 两步工作目录错位——压缩包生成在项目根，
   SHA256 步骤 cd dist 后找不到文件直接失败。统一落到 dist/
2. set -o pipefail 下的 SIGPIPE 误判：`find | head -n 1 | grep -q`、
   `zip --version | head -n 1`、`unzip -l | grep -q` 三处，
   head/grep -q 提前退出会让上游收到 SIGPIPE 使整条管道判失败。
   改为 find -print -quit 与先捕获到变量再 case 判断
3. 源码包 files: BiliArchive-Pro-v*.zip 靠 glob 匹配产物名，
   tag 格式变化会静默失配。改为从步骤输出显式取路径
4. Windows runner 镜像不保证预装 zip/unzip，补 Ensure archive tools 步骤
另外把最初写的 `"$BINARY" -c "import ..."` 冒烟检查删了——main.py 没有 -c
参数，那条永远走 fallback 形同虚设；换成真正有意义的版本号比对
- 未做：macOS x86_64 产物、代码签名与公证（需 Apple 开发者证书）、
  产物自动更新检查
- macOS 用户首次运行会遇到 Gatekeeper 提示，需右键打开或
  xattr -d com.apple.quarantine，已在计划书记录在案
