## 2026-10-14 - Task: M3-F4 跨平台自动发版流水线（已完成）

### What was done:
背景：build.spec 在 v1.4.0 已完成并本机验证（52MB 单目录产物），但每次发版
都靠手工跑打包 + 手工上传 Release。本任务把这条路径自动化。

- 新增 .github/workflows/release.yml，三作业依赖链：
  source（源码 ZIP）→ build（三平台矩阵）→ publish（统一转正式）
- 平台矩阵：windows-latest / macos-latest(arm64) / ubuntu-latest。
  关键约束：PyInstaller 不能交叉编译，所以三平台各占独立 runner，
  而不是矩阵里可替换的一个维度
- 每个平台构建流程：Ensure archive tools → PyInstaller 构建 →
  --version 冒烟并与 app/__init__.py 比对 → 关键依赖完整性检查
  （yt_dlp/bilibili_api/defusedxml/uvicorn）→ 打包 → SHA256 → 上传
- source 作业用 git archive 生成源码 ZIP，并审计条目：
  config.local.yaml / data/ / downloads/ / venv/ / 本地任务记录 命中即失败
- 发布策略：三平台产物先传草稿，全部成功后 publish 才转正式。
  任一平台失败不会产生正式 Release
- 产物内附 config.yaml / LICENSE / README.md / bin/ 空目录 / 中文安装说明
- 权限最小化：contents: write
- 文档同步：DEVELOPER_GUIDE 新增「自动化发版」小节、README 与 README.en.md
  打包章节改为「推送标签自动产出三平台」、CHANGELOG Unreleased、
  完善计划书 v5 + F4 执行记录

### Testing:
- YAML 解析与结构校验通过（.mimosa/check_release_yml.py）：
  触发器/作业链/矩阵/权限/必需步骤全部符合预期
- 断言三平台均为原生 runner（无交叉编译）
- 断言无 SIGPIPE 风险模式、无 CR 字符、无 PowerShell 语法混入
- 断言源码归档含敏感路径审计
- 未在真实 CI 上跑过（需推送 tag 触发），本地无法验证 PyInstaller
  在 macOS/Linux runner 上的真实产物

### Notes:
实现过程中修正了自己第一版写出的 4 个真实缺陷：
1. Package 与 Generate SHA256 两步工作目录错位——压缩包生成在项目根，
   SHA256 步骤 cd dist 后找不到文件直接失败。统一落到 dist/
2. set -o pipefail 下的 SIGPIPE 误判：`find | head -n 1 | grep -q`、
   `zip --version | head -n 1`、`unzip -l | grep -q` 三处，
   head/grep -q 提前退出会让上游收到 SIGPIPE 使整条管道判失败。
   改为 find -print -quit 与先捕获到变量再 case 判断
3. 源码包 files: BiliArchive-Pro-v*.zip 靠 glob 匹配产物名，
   tag 格式变化会静默失配。改为从步骤输出显式取路径
4. Windows runner 镜像不保证预装 zip/unzip，补 Ensure archive tools 步骤
另外把最初写的 `"$BINARY" -c "import ..."` 冒烟检查删了——main.py 没有 -c
参数，那条永远走 fallback 形同虚设；换成真正有意义的版本号比对
- 未做：macOS x86_64 产物、代码签名与公证（需 Apple 开发者证书）、
  产物自动更新检查
- macOS 用户首次运行会遇到 Gatekeeper 提示，需右键打开或
  xattr -d com.apple.quarantine，已在计划书记录在案

### What was done:

后端：
- 新模块 app/core/commands.py：命令通道。commands.json 与数据库同目录（与 runtime.json 同构）。
  * WebUI 只原子追加，核心只认领+回执；每次写入前重读文件，保证并发追加不丢命令
  * take_pending() 先标记 running 再返回 → 守护进程崩溃也不会重复执行（幂等认领）
  * 队列上限 32，审计历史上限 50；note/回执统一截断单行 200 字符（防审计日志注入）
  * asset_id 只接受 BV/av 正则白名单：拒绝任意字符串与文件路径（防路径穿越）
  * FORBIDDEN_COMMANDS 硬编码删除类指令名，双层拒绝
- main.py：
  * _dispatch_commands()：消费命令并逐条回执，单条失败不影响其余命令与扫描循环
  * _sleep_until_next_scan()：休眠由 asyncio.sleep(interval) 改为 5 秒分片轮询，
    trigger_scan 最多 5 秒内唤醒（新增 _loop_time() 注入点便于测试确定性时钟）
  * 轮次开始前额外消费一次命令，让 redownload_asset 在本轮巡检即命中
  * restart 抛 RestartRequested → daemon_loop 捕获后安全退出并关闭数据库，
